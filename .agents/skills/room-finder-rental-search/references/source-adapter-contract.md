# Source adapter contract

掲載元を追加するときは、サイト固有の取得処理を `api/crawler/<source>` に閉じ込め、共通のAgent評価・API保存・UI表示へ接続する。

## Adapterが扱うもの

- 検索URLと、掲載元が提供する検索フィルタ
- 許可するHTTPSホストと物件詳細URLの判定
- robots.txtの確認、User-Agent、リクエスト間隔、タイムアウト
- 検索結果からの掲載元物件IDと詳細URLの抽出
- 詳細ページから取得できる原文・構造化値・根拠位置の抽出
- 一時的なHTTP障害と、対象外・情報不足・条件不一致の分類

## 共通層が扱うもの

- ユーザー条件を必須条件として評価すること
- 必須条件ごとの判定結果と根拠を保持すること
- `matched=true` の物件だけをGo APIへ送信すること
- 保存APIの冪等性、再試行、重複排除、検索プロファイルとの紐付け
- 候補数・一致数・保存数・失敗数・未処理数の集計
- Web UIで保存結果を再確認すること

## 追加時の不変条件

- 掲載元のHTMLやURL形式を共通層に漏らさない。
- 掲載元に存在しない情報を推測しない。根拠のない必須条件は不一致または確認不能とする。
- 掲載元ごとにsource識別子とstate/checkpointを分離し、別サイトの再試行状態を混ぜない。
- DBやNeonへ直接接続せず、既存のGo API契約を使用する。
- robots.txtや利用規約に反する取得を行わない。
